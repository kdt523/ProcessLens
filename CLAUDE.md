# ProcessLens

A manufacturing root-cause analyzer with an LLM copilot. It answers one question: **which process parameters are linked to product defects, and how much can we trust that answer?**

Built on the public UCI SECOM factory dataset (id 179, 1,567 production runs, ~590 sensors, ~6.6% failures). It's a portfolio project aimed at a Jr. Data Scientist role (Michelin India), so data science rigor and honest communication matter more than flashy features.

The full phase-by-phase plan is in `PROCESSLENS_BUILD_PLAN.md`. Read it before starting any phase.

> **Scope override (owner, 2026-10-06):** skip Docker, docker compose and public deployment for now. The project runs directly on the host via `uv` + `make`. Everything else in the plan stays the same.

## What we're building

1. **Data audit + contract:** clean SECOM, check missing data and useless sensors, and validate with pandera.
2. **Defect prediction:** leakage-safe, time-ordered models (baselines → LightGBM), calibrated, with bootstrap CIs. Turned into a cost-based inspection policy ("inspect top x% → catch y% of failures").
3. **Root-cause ranking:** Mann–Whitney + BH-FDR, stability selection and SHAP, combined into one ranking and reported per cluster of correlated sensors.
4. **Planted-fault benchmark (the centerpiece):** inject known causes into the real data and measure hit@k, false alarms when there's no cause, and the smallest detectable effect. The results generate `docs/LIMITS.md`.
5. **LangGraph copilot:** Gemini Flash writes a structured root-cause report **only from tool outputs**. A verifier checks every number, and the copilot abstains when evidence is weak. Prompts v1 and v2 are compared in an eval harness.
6. **Production layer:** FastAPI, a Streamlit dashboard, PSI drift monitoring, MLflow, and GitHub Actions CI with quality gates. (Docker skipped for now.)

```
make audit       # data audit report
make train       # models + metrics + MLflow
make rootcause   # ranked suspects
make benchmark   # planted-fault benchmark
make agent-eval  # copilot eval (live LLM)
make api / make app
make test lint
make all         # rebuild everything from scratch
```

## Rules (always follow)

- **Work one phase at a time.** Plan first, implement, run the acceptance checks, commit, then stop for my review.
- **Never invent or hand-type numbers.** All metrics come from code and go into `reports/metrics/*.json`. The README tables are generated by `scripts/render_readme.py`. Report weak results honestly.
- **No leakage.** Every preprocessing step is fit on train only, inside an sklearn `Pipeline`. Splits are time-ordered. No SMOTE or feature selection before the split. The test set is used once.
- **Never call rankings "causes".** Say "suspects" or "associated with". This is observational data.
- **The LLM never sees raw rows** and never decides the cause. It only calls tools and explains, and unverified numbers are rejected.
- **Reproducible:** seed everything, keep all parameters in `configs/*.yaml`, and make sure `make all` works from a clean clone.
- **Code style:** type hints, short functions, docstrings on public functions, tests for every module, `ruff` clean.
- **Keep it focused:** no Kubernetes or Terraform. Ask before adding dependencies not listed above.
- LangGraph and LangChain APIs change often, so check the docs for the installed version before writing agent code.
- Keep `.env` (GEMINI_API_KEY) out of git. Agent tests run in record/replay mode, so CI needs no key.
